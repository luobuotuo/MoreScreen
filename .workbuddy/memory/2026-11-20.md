# 2026-11-20

## DTLS 曲线协商缺陷修复（提交 da64a16）★ 重要

### 现象
电脑浏览器（新版 Edge）访问接收端：`ICE connected` 但 `connection failed`，画面全黑。
平板（华为浏览器）一切正常。

### 定位路径（值得复用）
1. 先排除网络/代理：用 `getStats()` 拿 candidate-pair，确认 Edge 已选中
   `127.0.0.1 loopback 候选` 且 `nominated` —— 证明路径干净，不是代理劫持。
2. 加 `env_logger` + `RUST_LOG=webrtc_dtls=trace` 拿到底层错误：
   `Flight 0 result alert: Fatal/IllegalParameter, err: ErrInvalidNamedCurve`
   `Failed to start manager dtls: invalid named curve`

### 根因
`webrtc-dtls 0.11` 的 `src/flight/flight0.rs:114`：
```rust
state.named_curve = e.elliptic_curves[0];   // 只取第一个，不遍历
```
新版 Chromium 把后量子混合曲线 `X25519MLKEM768 (0x11ec)` 排在 supported_groups 首位，
`NamedCurve::from(0x11ec)` → `Unsupported` → `generate_keypair()` 报 `ErrInvalidNamedCurve` → 握手失败。
旧内核浏览器不发 PQ 曲线，所以平板正常。

上游 `webrtc-dtls 0.12.0` 已修（改成遍历），但 `webrtc-rs 0.12` 依赖约束是 `^0.11`。

### 解法
vendor 一份 0.11 到 `vendor/webrtc-dtls`（903K），只改该段为「遍历选第一个支持的曲线」，
`[patch.crates-io] webrtc-dtls = { path = "vendor/webrtc-dtls" }`。

注意坑：
- `[patch.crates-io]` 不能写 `{ version = "0.12.0" }`（报 "points to the same source"），
  必须指向不同源（path / git）。
- vendor 目录要删掉 `Cargo.lock` 和 `Cargo.toml.orig`。
- 用到 `NamedCurve` 时要写全路径 `crate::curve::named_curve::NamedCurve`（原文件没 import）。

### 验证
修复前本机 Edge 必失败；修复后：
```
connectionState: connected / iceConnectionState: connected
[webrtc] #1 诊断 conn=Connected ice=Connected
[ctl] #1 质量：上屏 30.0fps 丢包 0.00% RTT 1ms
```

### 长期
Chrome/Edge 会越来越普遍默认启用 PQ 曲线，所有基于 webrtc-rs 0.12 的项目都会踩。
待上游把 webrtc-rs 依赖提到 webrtc-dtls 0.12+ 后可移除 vendor。

## 另外两个 P2 回归修复

### renderState 未定义（913bfa0）
P2.7 调了 `renderState()` 但漏写定义 → 收到 offer 时抛 ReferenceError →
answer 永不生成 → 黑屏。
**教训：`new Function()` 语法检查查不出未定义标识符，前端改动必须抓 pageerror 做运行时验证。**

### QR 格式信息位置错（ebe3365）
`setF(14 - i, 8, bit)` 应为 `setF(SIZE - 15 + i, 8, bit)`。
i=8..14 时行号落在 6..0，写进了定位图形区 → 扫描器读不到格式信息 → 扫不出来。
**验证升级：反向读取矩阵 + RS 自校验**（结构检查发现不了位置错误；RS 校验通过才证明数据放置正确）。

## 重要结论修正：30fps 是平板最优帧率

| 发送 | 上屏 | 呈现率 |
|---|---|---|
| 20 fps | 13-14 | 68% |
| **30 fps** | **30.0** | **100%** |
| 60 fps | 29-35 | 55% |

之前记的"华为渲染上限 30-35fps"表述不准确 —— 30fps 正好是其渲染工作点，每帧完整呈现。
**默认 30fps 不是妥协，是正确选择。**

## 环境事实（新增）

  但本次根因不在代理（loopback nominated 仍失败，最终是 DTLS 算法）。
- 虚拟屏索引持续漂移：DISPLAY44 → DISPLAY47，**必须用 --display 匹配，不能用下标**。
