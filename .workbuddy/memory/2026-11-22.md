## 1080p30 长稳实测 + 三个新问题的诊断（22:00~22:15）
- 用户实测（21:59，会话 #7，1080p30）：header 26.2fps / **【上屏】15.8fps** / 缓冲 **374ms** /
  丢帧 1558/1964（16.5%）/ 丢包 0.03% / RTT 8ms / 控制通道 open·759ms / 玻璃到玻璃「未开启」。
- **结论修正**：1080p30「通过」只对宿主编码侧成立；**华为平板解码渲染 1080p 只有 ~16fps**
  → 1080p30 不可用，实际能力约 720p30。docs/06 §4.1 高分辨率吞吐不足仍成立（瓶颈在接收端）。
- **用户反馈「控制本机有时点几下没反应，宿主鼠标代点有效」**：注入链路正常（宿主直点有效），
  根因是 374ms 缓冲 + 15.8fps 上屏导致的操作反馈滞后（点了画面没更新 → 以为没反应）。
- **玻璃到玻璃「未开启」**：探针色块在画面上可见，但接收端样本为 0；已加诊断日志区分
  「v=null（drawImage 失败）/ v=0（取到黑帧，鸿蒙浏览器 video→canvas 兼容性）/ 延迟超窗口」，
  并加 `?noe2e=1` 开关做 A/B（验证 canvas 读帧是否拖累上屏）。
- 5% 丢包会触发看门狗重连（缓冲>1000ms 10s）——符合设计，但频繁重连体验差，待降码率机制解决。
- 待 A/B 结论：① 探针采样是否拖累上屏；② 切 720p30 后上屏是否回到 30fps。
