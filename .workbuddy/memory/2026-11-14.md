## 项目：remote-screen（多屏扩展，对标 Deskreen）

### 背景
- 调研 Deskreen（Electron + React + TS + simple-peer/WebRTC + Koa/Socket.IO 本地信令，AGPL-3.0，CE 功能受限、Pro 未开源）。
- 结论：国内没有"接收端只需浏览器"的同类；最接近的是 ExtensoDesk / EV扩展屏 / ToDesk 扩展屏 / 向日葵副屏 / UU远程无线副屏。
- 架构定调：宿主 UI 用 Tauri 2 + React + TS，核心用 Rust，采集/编码/驱动用平台原生（C++/Swift）。
  **POC 阶段先用 Rust 直接写 CLI，验证通过后再包 Tauri/Rust Core**（先打通可测量链路，不先做 UI）。

### 关键结论 / 踩坑（重要）
- **本机代理 127.0.0.1:64796 不可用**：必须 `curl --noproxy '*'`，cargo 侧必须同时设 `no_proxy=*`（只清空 proxy 变量不够）。
- **debug 版 cargo test 产物在本机被拒绝执行（WinError 5）**，普通二进制与 `--release` 测试均正常 → 一律用 `--release` 跑测试。
- **工作区内新生成的 .exe 会在命令结束后被回收** → 必须把 `CARGO_TARGET_DIR` 指向系统临时目录。
- **Windows SDK 只有旧版本、无 MSVC Build Tools** → 选 Rust GNU 宿主 + 预装 MinGW（D:\mingw64x2）。
- **windows 0.61 API 易踩坑**：DEVMODEW.dmSize 是 u16；位置在 `dm.Anonymous1.Anonymous2.dmPosition`；
  `EnumDisplaySettingsExW` 第二参是 `ENUM_DISPLAY_SETTINGS_MODE` 新类型；`ChangeDisplaySettingsExW` 返回 `DISP_CHANGE` 新类型。
- **本机三个虚拟适配器在未建立客户端会话时不暴露任何模式**（模式列表为空）→ 要点亮需自装静态 VDD 或让对应客户端连一次。
