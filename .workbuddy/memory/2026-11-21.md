## P2 收尾：输入回传坐标映射实测（完成）

### 新增可复现实测探针
`crates/host-win/examples/verify_input.rs`：枚举每块屏 → 送光标到 4 个归一化点 →
`GetCursorPos` 读回逐像素比对；含 SetCursorPos 回读基准、接缝扫描、DPI_SHIFT 分类。
运行：`source scripts/env.sh && cargo run --release -p remote-screen-host-win --example verify_input`

### 实测抓到并修复的两个真实缺陷
1. **虚拟桌面原点未减**：`bounds` 来自 dmPosition（可为负），SendInput VIRTUALDESK
   的 0~65535 是相对整个虚拟桌面矩形，必须减 `SM_XVIRTUALSCREEN/SM_YVIRTUALSCREEN`。
   本机原点 (0,0) 碰巧正确，负坐标布局会整体偏一块屏。已改为 `virtual_desktop_geometry()`。
2. **进程 DPI 无关导致坐标口径分裂**：主屏 `GetSystemMetrics`=1536x864（125% 虚拟化），
   `EnumDisplaySettings`=1920x1080（物理），虚拟桌面 3200x864（宽物理/高虚拟混合）。
   表现：主屏 (1,1) 落到 (1535,690)、虚拟屏 (0,0) 落到 (1535,0)、
   `SetCursorPos(960,1000)` 回读成 (1920,719)（屏幕下部不可达）。
   **修复：`main()` 第一行调用 `input::init_dpi_awareness()` → `SetProcessDPIAware()`。**
   修复后主屏四角全 PASS，底部恢复可达。

### 关键度量教训
- **SendInput 是异步注入**：固定 sleep 30ms 读回会读到旧位置，第二次跑从 7/8 掉到 3/8。
  必须轮询到光标位置连续 3 次不变再读（探针里 `cursor_settled()`）。
- 用 `SetCursorPos(物理像素)` 回读做基准，可干净区分「我们算错」与「OS 自己重定位」。

### 最终结果
`7 PASS / 1 DPI_SHIFT / 0 其它 FAIL`（8 点），PASS 误差 ≤1px。

## 真机反馈："拖动时跳动/晃动" → 多标签并发解码（已修）

### 数据（宿主日志，4 个客户端同时连）
| 客户端 | 上屏 | 缓冲 | RTT | 丢包 |
|---|---|---|---|---|
| #3 | 26~28fps | 214~219ms | 7~20ms | 0% |
| #2 | 12.0fps | 52ms | 2~10ms | 0% |
| #4 | 10.0fps | 290~359ms | 2~11ms | 0% |

丢包全 0%、RTT 正常 → 不是网络，是**接收端解码/渲染被拖垮**。
同一浏览器多开 `webrtc.html`，每个标签各自解码一路 720p，抢 CPU/GPU；
浏览器还节流后台标签渲染 → 后台标签稳定 10~12fps。
**用户关掉多余标签后立刻回到 27~30fps，根因确认。**

### 修复：同源多标签互斥（web/receiver/webrtc.html）
- `BroadcastChannel('rs-receiver')` 探测；已有标签在接收时，新标签禁用「开始接收」并提示。
- 页面加载即探测（不等点击）；旧标签 `pagehide` 广播 `bye` 自动解锁；1s 心跳。
- **检查必须同步（不 await）**，否则丢失用户手势 → `requestFullscreen` 被拒。
- 多设备（平板+电脑）不受影响：BroadcastChannel 只在同源同浏览器内通信。

### 验证
`new Function` 语法 OK；Edge headless 加载后按钮为初始态「点击开始接收」，无 Uncaught/ReferenceError。
**未验证**：双标签互斥的实际触发（headless 单进程构造不出同源双标签），需现场开两个标签确认。

### 服务运行环境坑
后台任务会被外部清理（25 分钟时终止，无 panic/无收尾日志）。判断是会话/任务清理，非程序问题。
`--seconds` 默认 60（main.rs:476-478），长跑必须显式给。

### 已补：自动重连（提交 a98ed76）
- 断线重建**整条会话**：关旧 PC + 关 WS → 宿主 `poll_disconnected` 销毁旧会话 → 重新信令。
- `failed` 立即重连；`disconnected` 给 2 秒自愈窗口（ICE 抖动常自愈）。
- 指数退避 0.5→1→2→3s 封顶，上限 20 次后停止提示刷新。
- 关键坑：主动关 WS 前必须 `ws.onclose = null`，否则触发自身重连（代码里用 closingForReconnect 标志）。
- 语法+headless 验证通过；**端到端未验证**（需停服务再起，看是否自动恢复）。
