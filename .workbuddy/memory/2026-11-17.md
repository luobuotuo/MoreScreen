### 关键技术决策

**1. 画质协商不做运行时改码率**
- 外部 ffmpeg 无运行时改编码参数接口；重启编码器要黑屏 1-2 秒且打断所有会话
- 采用「上报 + 建议」：零中断，由用户决定是否重启
- 真正的自适应需**进程内编码器**（P4 方向）

**2. 自研 QR 编码器（web/receiver/qr.js）**
- 范围有意收窄：Byte 模式 + 版本 3（29x29）+ 纠错 L + **固定掩码 0**
- 固定掩码合法（标准要求解码器支持全部 8 种），省掉罚分计算，缩小出错面
- 容量 53 字节，够编码 `http://192.168.0.107:8788/webrtc.html`（34B）
- **验证**：尺寸 29 ✅ / 定位图形 ✅ / 定时图形 ✅ / 暗模块 ✅ / 对齐图形 ✅ /
  **`formatInfo(0) = 0x77C4` 与标准值完全一致** ✅ / 超长返回 null ✅

**3. 输入回传双重安全闸**
- 宿主 `--allow-input`（未开启时 handle_ctl 直接 return）
- 接收端「控制本机」按钮（未点不发事件）
- 坐标口径：画面归一化 0~1 → 目标屏 bounds → SendInput 0~65535 + VIRTUALDESK

**4. 控制消息走 DataChannel 而非 WS**
- 与媒体同路径、延迟更低、天然按会话隔离（每 pc 一条 ctl 通道）

### 本次补测到的硬件事实

**虚拟屏索引会漂移**：同一块 MttVDD 从 DISPLAY76 漂到 DISPLAY44（跨天/重启后）。
→ 必须用 `--display MttVDD` 或设备路径匹配，**不能用下标**（此坑早已记录，本次再次实测印证）。

**虚拟屏可用模式**（实测枚举，36 种）：800x600 / 1280x720 / 1366x768 / 1920x1080 /
2560x1440 / 3840x2160，每档 30/60/90/120/144/165Hz。

### 已知限制（已写入 docs/06）

1. **1280x720@60fps 编码产出 93.4%**（与码率无关，两轮各 1 小时实测）：
   单帧 3.7MB × 60 = 221MB/s 超出回读+编码吞吐 → 该分辨率建议配 30fps
2. **华为平板渲染上屏上限 30-35fps**（解码完整 framesDropped=0，属设备限制）
3. 画质协商只上报不自动改码率（见决策 1）
4. 键盘映射未处理修饰符状态机（Ctrl+C 会分别按 Ctrl 和 C，多数场景可用）
